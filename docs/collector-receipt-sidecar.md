# Collector receipt sidecar

Each durable capture inbox record may have a sibling `<session>-<sequence>.receipt` containing exactly `FQR1,<16hex-session>,<uint32-sequence>,<uint64-epoch-ms>,<0-or-1-clock-plausible>,<8hex-crc32>\n` in ASCII. CRC32/ISO-HDLC covers all bytes before the comma introducing the checksum. The history indexer accepts it only when the sidecar identity matches the `.fqi` filename and its exact length, syntax, checksum, and clock-plausibility fields validate. Only flag `1` with epoch 1704067200000..4102444800000 ms is retained as `sample.collector_received_ms`; flag `0` must pair with epoch `0`. Implausible, absent, malformed, or corrupt sidecars remain SQL `NULL`. The reader never replaces device capture UTC or display time with receipt time.

The retained timestamp is an approximate collector host wall-clock stamp made after durable inbox publication. It is not independently verified and does not prove NTP synchronization. Grafana shows it separately from device capture UTC and computes an approximate capture-to-receipt wall-clock offset only when both timestamps exist. That estimate may include host/device clock offset and must not be interpreted as a verified network transfer latency.
